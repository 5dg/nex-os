# Experimental image base diagnostic

This opt-in hosted job is a synthetic diagnostic, not a release or production assessment. It retains scanner output and reports failures; it does not change release gates or suppress findings.

In run 41020446572 the first, PostgreSQL image scan stopped when monitored filesystem growth exceeded its 1 GiB forecast. The source of that growth and the amount needed to finish are unknown. For a fresh run, the PostgreSQL scan forecast is 2 GiB and is admitted only with at least 4 GiB free on both the output and Docker filesystems. Workspace and Guard scans retain their 1 GiB forecasts and 3 GiB admission thresholds. All scans retain the 2 GiB reserve and stop when their forecast or the reserve is exceeded; this increase does not guarantee that PostgreSQL scanning will finish.

The build client may not prove BuildKit daemon quiescence after interruption. The job halts later phases on build failure, but termination of the disposable hosted runner remains the remaining control. Post-scan database metadata is retained per role when available and is not proof of its freshness or identity during scanning. Raw artifact contents are not asserted to be secret-free.

A later scan also exceeded the 2 GiB forecast with an empty report. Its allocation source remains unknown. Trivy 0.76.1 can export the Docker image into a temporary `docker-export-*` file before scanning; its source is documented in [the Docker image adapter](https://github.com/aquasecurity/trivy/blob/v0.76.1/pkg/fanal/image/daemon/docker.go) and [image reader](https://github.com/aquasecurity/trivy/blob/v0.76.1/pkg/fanal/image/daemon/image.go). This is a candidate explanation, not a diagnosis of the earlier run.

For a fresh diagnostic, only the scanner receives a private per-role `TMPDIR` on the monitored output filesystem. A separate bounded sampler emits numeric high-water snapshots for recognized Docker export, Trivy DB and scan-cache files, and free-space decreases on the monitored filesystems. It also reports the Docker image's inspected size, which is not an export-size measurement. File names, paths and contents are not emitted by telemetry. Sampling can miss short-lived peaks, follows no links, has entry and sample limits, and does not account for every allocation; shared filesystem changes prevent exclusive attribution. A partial or unavailable sample is not evidence of zero growth. The scanner cache must be on an already monitored filesystem, and the diagnostic stops before later roles if its sampler cannot be stopped.

These measurements do not alter the existing scan budgets, reserve, output limits, timeout, or release gate. Raw scanner artifacts remain retained separately and are not claimed secret-free.
